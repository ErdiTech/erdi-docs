## Protocol summary

- Frame: 8 bytes, header `55 AA`, then function code, four data bytes, checksum.
- Default baud: 115200 bps, 8 data bits.
- Transmit checksum: lower 8 bits of function code + D1..D4 (the header is not included).
- Reply checksum: lower 8 bits of header H + header L + function code + D1..D4 (the header is included). The two formulas differ on purpose.
- Reply to a ranging command: `55 AA <fn> STA FF DIS_H DIS_L SUM`. `STA = 1` means the measurement succeeded.
- Distance: `DIS_H:DIS_L` is the measured value in metres multiplied by 10.

| Command | Request frame |
|---|---|
| Single-shot ranging | `55 AA 88 FF FF FF FF 84` |
| Continuous ranging | `55 AA 89 FF FF FF FF 85` |
| Stop ranging | `55 AA 8E FF FF FF FF 8A` |
| Angle measurement | `55 AA 8A FF FF FF FF 86` |

:::caution Continuous ranging
For this model the manual's continuous-ranging request uses function byte `0x89` while the recorded reply uses `0x88`. Poll with single-shot (`0x88`) until ERDI confirms the behaviour for your batch.
:::

The full frame description is in [Family A protocol](../protocols/family-a-55aa.md). Try it without installing anything in the [browser serial monitor](../tools/serial-monitor.mdx).

## Code examples

<Tabs groupId="lang">
<TabItem value="python" label="Python" default>

```bash
pip install erdi-lrf   # PyPI, MIT
erdi-lrf --port /dev/ttyUSB0 --model LRF1200A1 measure
```

```python
from erdi_lrf import ErdiLRF

with ErdiLRF("/dev/ttyUSB0", "LRF1200A1") as lrf:   # COM3 on Windows
    r = lrf.measure()                          # single-shot (0x88)
    print(f"{r.metres:.3f} m", "raw", r.raw)
```

</TabItem>
<TabItem value="arduino" label="Arduino">

```cpp
#include <ErdiLRF.h>

ErdiLRF lrf(Serial1, ERDI_LRF1200A1);

void setup() {
  Serial.begin(115200);
  Serial1.begin(erdiDefaultBaud(ERDI_LRF1200A1));   // 115200 baud; ESP32: Serial1.begin(baud, SERIAL_8N1, RX_PIN, TX_PIN)
  lrf.setTimeout(1000);
}

void loop() {
  ErdiMeasurement m;
  if (lrf.measure(&m) == ERDI_OK) {
    Serial.println(m.metres, 3);
  }
  delay(200);
}
```

## Known issues

- The datasheet notes that the send and receive checksums are computed over different bytes (see Protocol). Use separate functions for the two directions.
- UART logic level is not stated as a separate field for most models. Supply voltage is not the UART voltage: check the module's TX level against your host before wiring, or ask us.
